# SAT crystal design — API reference

Generated by reading `pypatchy/design/sat/polycube_sat_problem.py`,
`sat_problem.py`, `solve_params.py`, and `solution.py` directly. Re-check
against those files for anything you depend on being exact — this subsystem
changes often (e.g. `TorsionType.PARTIAL` post-dates the module's own
top-of-file docstring, which still only describes a binary torsion scheme).

## The SAT variable scheme (`PolycubeSATProblem`)

Indices: colors `1..c..#c`, species/cube-types `1..s..#s`, patch slots
`0..p..5` (the 6 face directions, [[polycubes-rules]]' `RULE_ORDER`),
positions `1..l..#l` (vertices of the target topology), rotations
`1..r..#r`, orientations `o` (patch alignment states).

| Variable | Meaning |
|---|---|
| `B(c1, c2)` | Color `c1` binds with color `c2`. |
| `F(l, p, c)` | The patch at slot `p` of position `l` (in the target topology) has color `c`. |
| `C(s, p, c)` | Patch `p` on species `s` has color `c`. |
| `P(l, s, r)` | Position `l` is occupied by species `s` at rotation `r`. This is the variable `PolysatSolution.spatial_map` is decoded from. |
| `O(s, p, o)` | Patch `p` on species `s` has orientation `o` (added alongside `TorsionType`; not in the module's original docstring). |
| `A(l, p, o)` | Position `l`'s patch `p` has orientation `o`. |
| `D(p1, o1, p2, o2)` | Orientation-compatibility between two patch/orientation pairs (used for `FULL`/`PARTIAL` torsion binding checks). |
| `T(c)` | Color `c`'s binding requires torsional (orientation) compatibility — only meaningful/present under `TorsionType.PARTIAL`, where this is itself a free variable the solver chooses per color, rather than a global setting. |
| `N_single(s)` / `N_multi(s, t)` | Nanoparticle-type assignment variables (single- vs. multi-nanoparticle-type problems). |

`rotation(p, r)` — encoding function: which patch slot `p` rotates to under
rotation `r`.

## `TorsionType` (enum, `NONE` / `FULL` / `PARTIAL`)

- `NONE` — no orientation machinery at all (no `O`/`A`/`D` variables);
  patches bind on color alone. Matches the pre-enum `torsion=False`.
- `FULL` — every bound color pair requires orientation compatibility.
  Matches the pre-enum `torsion=True`.
- `PARTIAL` — orientation machinery exists for every patch, but whether a
  *given color pair* needs orientation compatibility is a free SAT variable
  (`T(c)`) the solver chooses — a single solution can mix torsional and
  non-torsional color pairs. This is what `tlm_runner.rule_to_interaction_matrix()`
  (see [[tlm-simulations]]) exists to translate correctly into libtlm's
  per-angle interaction matrix, since libtlm's own `generateInteractionMatrix()`
  only supports one global torsion switch.
- `TorsionType.from_input(value)` accepts a `TorsionType`, the legacy bool
  encoding (`True`→`FULL`, `False`→`NONE`, for old spec/`problem_info.json`
  files), or a matching string.

## `PolycubeSATProblem` (extends `SATProblem`)

Constructor: `PolycubeSATProblem(nS, nC, nD, nL, nNPT, torsion_type: TorsionType)`.

Constraint-generation methods (called by `Polysat.init()`/`generate_clauses`,
not usually called directly): `add_constraints_all_particles`,
`add_constraints_all_patches`, `add_constraints_all_patches_except`,
`add_constraints_fixed_blank_orientation`, `add_constraints_no_self_complementarity`,
`fix_particle_colors`, `fix_empties`, `fix_slot_colors`,
`fix_all_color_interactions`, `fix_color_interaction`, `generate_BCO`
(builds the `B`/`C`/`O` variable blocks — must run before symmetry-breaking
clause generation, which references them), `gen_symmetry_breaking_clauses`
(canonical-form constraints; `_gen_species_ordering`/`_gen_rotation_canonical`/
`_gen_color_ordering` are its pieces), `gen_legal_color_bindings`,
`gen_partial_torsion_consistency`, `gen_legal_species_coloring`,
`gen_legal_species_orientation`, `gen_legal_patch_coloring`,
`gen_legal_position_patch_orientation`, `gen_forms_desired_structure`,
`gen_hard_code_orientations`, `gen_legal_species_placement`,
`gen_legal_species_position_coloring`, `gen_legal_species_patch_orientation`,
`gen_lock_patch_orientation`, `gen_nanoparticle_singleparticle`,
`gen_nanoparticle_multiparticle`, `gen_no_self_interact`,
`gen_req_mf_any_shared`/`gen_req_mf_all_shared` (multifarious-type
requirements).

Variable accessors (map a semantic variable to its SAT integer index):
`B`, `T`, `D`, `F`, `A`, `C`, `O`, `P`, `orientation`, `N_single`, `N_multi`.

Conversion: `solution_from_rule(rule, start_color_count=2) -> list[int]`,
`problem_part_from_rule(rule, start_color_count=2) -> SATProblemPart` — pin
an already-known rule's `C`/`O`/`T` variables as unit clauses, used by
`design_rule.verify_rule_against_topology()` to check a hand-authored rule
against a topology without running an open search.

Sizing/estimation (static methods, used for the pre-solve size warnings and
`MultiSolver`'s memory gate): `estimate_size(nS, nC, nD, nL, nNPT,
torsion_type, n_bindings) -> (n_vars, n_clauses)`,
`estimate_symmetry_breaking_size(nS, nC, nP=6, nR=24) -> (n_vars, n_clauses)`,
`estimate_solution_space(nS, nC) -> float`.

`check_bindings(bindings)`, `save_problem_info(save_to, bindings)` (writes
`problem_info.json`). `num_variables()`/`num_clauses()`/`output_cnf()`/
`describe()`/`describe_brief()`/`list_vars()` are inherited from the base
`SATProblem` (`sat_problem.py`).

## `clause_generation.generate_clauses(problem, topology, skip_clauses=[])`

Populates a `PolycubeSATProblem` with the full standard clause set for a
given target `TypedStructure`. `skip_clauses` names problem parts to omit —
`NegativeDesignStep._get_or_build_ot_problem()` skips `"E"` (`fix_empties`)
when building an off-target sub-problem from a *cropped* competing crystal
fragment, since boundary faces that bonded to a since-excluded neighbor
would otherwise be misclassified as "must be empty" and make the sub-problem
practically unsatisfiable.

## `SolveParams` — field reference

Built by `SolveParams(name, **kwargs)` or `load_solve_params(path, nColors, nSpecies)`.

- `topologies: list[GenericTypedStructure]` — one per component (multifarious
  problems have more than one; a plain crystal/finite target has exactly one).
- `bindings` / `extraConnections` — accumulated intra-unit-cell / periodic
  edges across all components, vertex-ID-remapped to avoid collisions.
- `nanoparticles: list[int] | dict[int, int]` — a list when there's one
  nanoparticle type, a dict (vertex → type) for multiple.
- `nS`, `nC`, `nDim` (default 3) — search-space bounds; `nS`/`nC` are usually
  overwritten per-attempt by `MultiSolver`/`construct()`.
- `torsion` (bool, legacy input key — translated via `TorsionType.from_input`).
- `crystal: bool` — auto-detected from `len(extraConnections) > 0 or
  len(topologies) > 1` unless given explicitly; this is what selects the
  crystal vs. finite-target default step pipeline.
- `maxAltTries` (default 10), `nSolutions` (default 1 — how many WEAK_PASS
  candidates to collect before giving up and returning them for review),
  `solver_timeout`.
- `pre_forbid_solutions: list[Path]` / `pre_forbid_jsonl: list[Path]` — parsed
  from a `pre_forbid` kwarg list of paths (a directory → a single forbidden
  solution; a `.jsonl` → re-derive a whole forbid list, see "reforbid" in the
  main doc; a `.txt` → `add_pre_forbidden_from`).
- `includeCanonicalConstraints` (default `True`), `canonical_constraints_max_clauses`
  (default 3,000,000) — see the main doc's "Building SolveParams" section.
- `steps: list[SolveStepSpec]` — the pipeline; `SolveStepSpec(step_class: str,
  step_kwargs: dict)`.
- `summerizeInterval` (default 0, meaning off) — log a rejection-count
  summary every N tries.

Helpers: `set_step_kwargs(step_class_name, **kwargs)` (mutate an existing
step's kwargs in place), `est_cpus_per_solve()` (max, not sum, across
`_STEP_CPU_ESTIMATORS`-covered steps — steps run sequentially within one
solve), `construct(name, min_nC, max_nC, min_nS, max_nS, max_diff, **kwargs)`
(build a whole grid of `SolveParams`, smallest-`nS+nC`-first), `targets_from_spec(params)`
(build `(targets, periodic_targets)` without instantiating a full `Polysat`).

## `PolysatSolution` (extends `SATSolution`) — method reference

Construction: `PolysatSolution(sat_problem, sat_results: frozenset[int],
target_structure)` — normally produced by `SATSolveStep`, not called directly.

- `.rule -> PolycubesRule`, `.decRuleNew() -> str` (the rule string).
- `.spatial_map: list[tuple[int, int]]` — per-position `(species, rotation)`,
  decoded from `P(l,s,r)` variables; index `l` matches the target topology's
  vertex numbering.
- `.nanoparticle_map: dict`, `.hasNanoparticles() -> bool`,
  `.numNanoparticleTypes() -> int`.
- `.type_counts() -> list[int]` — per-species instance counts for one
  unit-cell/target copy; `.mf_type_counts(tops)` — the per-component
  breakdown for a multifarious solution.
- `.to_polycube() -> PolycubeStructure`, `.has_coord_map() -> bool`,
  `.exportScene(modelname="scene")`, `.cubeToJSON(i)`.
- `.describe() -> str` — human-readable summary (this is what's written to
  each solution's `soln_info.txt`).
- `.printToLog(logger=logging.root)`.
- Inherited from `SATSolution`: `.raw` (the underlying `frozenset[int]` model
  — lazily reloadable from `._save_path` after `.release_raw()` frees it to
  save memory once a solution is forbidden), `.get_vars(var_name)`,
  `.get_C_vars()`/`.get_O_vars()`/`.get_T_vars()` (and the `C_vars`/`O_vars`/
  `T_vars` property aliases), `.dump_vars(fp)`, `.dump_var_names(fp)`.

## `SolveStep` / `StepResult` — field reference

`StepOutcome` (enum): `PASS`, `WEAK_PASS`, `REJECT`, `TERMINAL`.

`StepResult` (dataclass): `outcome: StepOutcome`, `solution: PolysatSolution
| None`, `constraints: list[TypedStructure]` (newly-discovered off-targets to
feed `NegativeDesignStep`), `response: SolverResponse | None` (set only on
`TERMINAL`), `message: str`, `details: dict` (structured extra context,
surfaced verbatim into the `PolysatLogger` "reject" JSONL event).

`SolveStep` (ABC): `run(soln, solver) -> StepResult` (abstract),
`name()` (class name), `descriptor()` (short per-instance parameterization
string, e.g. distinguishing two `VirtuallySeededGrowthDesignStep`s at
different temperatures — empty by default), `label()` (`"[index]ClassName(descriptor)"`,
used in logs), `record_rejection(soln, result)`, `report()`. Every step's
`__init__` takes `save_rejected: bool = False` (keep rejected
`(soln, result)` pairs in memory for `report()` to print, e.g. in a test).

`GiveUpReason` (enum, `design_rule.py`) — what a `None` return from
`Polysat.find_solution()` actually means: `SOLVER_TIMEOUT`,
`SOLVER_UNHANDLED_RESPONSE`, `WEAK_PASS_PENDING_REVIEW`,
`MAX_TRIES_EXHAUSTED`, `WORKER_EXCEPTION` (an uncaught exception inside
`Polysat`, caught at the `multisolve.py` worker-process boundary instead of
propagating). Read `polysat.give_up_reason` after a `None`/`False` result.
